# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**FCC Studio** — an Electron desktop IDE for [free-claude-code (FCC)](https://github.com/Alishahryar1/free-claude-code). Instead of running `fcc-claude` separately in a terminal, everything lives in one Electron app: file explorer + Monaco editor, a chat panel that talks to Claude through the FCC proxy, an integrated xterm terminal, and FCC server health management. It is deliberately small.

## Commands

```bash
npm run dev          # electron-vite dev (HMR renderer, restarts main/preload)
npm run build        # electron-vite build (main + preload + renderer → out/)
npm run preview      # electron-vite preview
npm run typecheck    # tsc --noEmit for both node + web tsconfigs
npm run test         # vitest run (tests/ — git-ignored, dev-only)
npm run smoke        # node smoke/sdk-smoke.mjs — live FCC proxy round-trip check (uses the SDK directly, not the app's chat path)
npm run icons        # electron scripts/generate-icons.mjs — re-render build/icon-*.png + icon.ico from resources/icon.svg
npm run dist:win     # build + electron-builder NSIS Windows installer
```

To run a single test file: `npx vitest run tests/path-utils.test.ts`.

## Architecture

Electron 3-process layout under `electron-vite`, with a shared module imported by all three via the `@shared` alias (`src/shared`):

- **`src/main`** — Node side (CJS, bundled). `index.ts` creates the `BrowserWindow` and wires IPC; `ipc.ts` registers every handler; `file-service.ts`, `terminal-service.ts` (node-pty), `fcc-manager.ts` (FCC server health/start), `cli/cli-runner.ts` + `chat/chat-host.ts` (claude CLI subprocess engine).
- **`src/preload`** — exposes `window.fcc`, a typed promise-based API over `ipcRenderer.invoke`/`.on` (see `FccApi` type). The renderer never touches `ipcRenderer` directly.
- **`src/renderer`** — React + Zustand. Stores under `src/renderer/src/stores/`, components under `components/`, UI theme in `styles.css` (warm-dark terracotta palette, CSS variables; UI font is **Comic Neue**, mono is **JetBrains Mono** — both bundled via `@fontsource` and imported in `main.tsx`). Monaco is themed via `monaco-setup.ts` (`fcc-dark`/`fcc-light` themes, worker config). The app has a custom HTML titlebar (`Titlebar.tsx`) over a hidden native titlebar; the window caption buttons are re-tinted per theme through IPC (see constraints).

State flow: renderer calls `window.fcc.*` → main handles → pushes events back over `ipcRenderer.on` channels. Chat and FCC status are push-driven (channels `chat:event`, `fcc:status-changed`, `term:output`); file ops are invoke/response.

**IPC contract** — channel names live in `src/shared/ipc.ts` (`IPC` const + `evt*` event names). Main→renderer events use the `evt*` prefix to distinguish them from invoke channels. Never rename a channel without updating preload + both sides; the term channels deliberately use `term:output` (not `term:data`) to avoid colliding with the invoke channel `term:data`.

## Non-obvious constraints (all verified empirically)

- **Chat drives the `claude` CLI as a subprocess** (Path B — full extension parity), not the Agent SDK. `cli-runner.ts` spawns the binary with `--input-format stream-json --output-format stream-json --verbose --model <model> --max-turns <n> --permission-mode acceptEdits`, writes user turns to stdin as `{"type":"user","message":{...}}`, and reads `\n`-terminated JSONL events from stdout. The binary resolves via `CLI_PATH` env > the SDK's bundled platform package (`node_modules/@anthropic-ai/claude-agent-sdk-<platform>/claude.*`) > PATH.
- **Subagents are surfaced via `--forward-subagent-text`** (always on — the CLI otherwise hides subagent output over stream-json). It tags forwarded subagent text/thinking/tool blocks with `parent_tool_use_id`; the reducer nests those into child `ChatMessage`s (parentId = the owning Agent/Task message's id) and the **Subagents sidebar view** (`SubagentPanel.tsx`, `sidebarView:'subagents'`, activity-bar sparkles icon) groups them per spawn call showing transcript + thinking + tool calls. A subagent tool never resolves on the *last* message, so the `user`/`tool_result` case scans **every** message for a matching `tool_use_id`. The reducers elsewhere must keep `isAssistantTurn` requiring `!parentId` — main-turn text must not merge into a nested child.
- **Model effort is selectable and auto-snapped, and changes live.** `settings-store` holds raw `chatEffort` ('auto' | low|medium|high|xhigh|max|ultracode); `effectiveEffort(model, chosen)` snaps a too-high choice down to `effortCap(model)` (Opus 5/Fable 5 → ultracode; Sonnet 5 → xhigh; Haiku 4.5 → no effort → 'auto'). The chat-settings UI and `App.tsx`'s `setChatSettings` push the *effective* value; `config.ts` → `chat-host.spawn` → `cli-runner` passes `--effort` (guard: only `low..max,ultracode`) for fresh spawns, AND on an effort change the UI sends a live `apply_flag_settings` control (below) so the **current** chat's next turn uses it. `FCC_CHAT_EFFORT` supplies a headless default.
- **Realtime mode/effort via the SDK control protocol (`chat:control`).** Editing flags only at spawn would confine changes to the next conversation — so the app sends **`control_request` envelopes** to the running CLI's stdin: `CliSession.sendControl(subtype, request)` writes `{"type":"control_request","request_id":"ctl-…","request":{subtype,…}}`. `set_permission_mode {mode}` switches Plan/Act **immediately** (verified: the CLI replies `control_response` success + a `system/status` echoing the new `permissionMode`); `set_model {model}` switches the model on the next model call of the current turn (verified: success response — the chat-model picker sends it live); `apply_flag_settings {settings:{effortLevel|ultracode|effortLevel:null}}` applies effort on the **next turn** (`effortControlSettings()` in settings-store builds the payload). These are handled locally by the CLI and never touch the FCC proxy, unlike the unreliable `interrupt`. `chat-host.control()` forwards to the live session and keeps its stored spawn-mode in sync; `chat-store.control()` is the renderer entry (no-op with no live session). Control responses are ignored by the reducer and `history.record` (its `default:` branch). **Shift+Tab / the Plan button call `toggleMode()`** which flips `planMode` AND sends `set_permission_mode` — so mode now switches on the current chat, not only the next. Control, plus model/turn settings, still matter at spawn: a respawn re-reads `getChatConfig()`. The same plumbing drives a few more live knobs — `apply_flag_settings {fastMode}` / `{alwaysThinkingEnabled}` (fast-mode + thinking toggles, palette entries `chat-store.toggleFastMode/toggleThinking`) and live MCP controls `mcp_toggle {serverName,enabled}` / `mcp_reconnect {serverName}` (MCP settings tab On/Off + ↻ buttons). **Status bar is live**: the reducer's `system/status` case folds the echoed `permissionMode`/`model` into `chat-store.liveStatus`, shown next to the model-snapped effort. **CLI thinking blocks carry the text in the `thinking` field, not `text`** (short tool-selection thoughts can be signature-only, `thinking:''`), so the reducer reads `b.thinking` and `ChatMessage` renders it as a foldable `.msg-thinking` block.
- **Workflow/task progress streams over persistent stream-json and powers the Subagents panel's "Running" list.** A live multi-agent run emits `system:task_started {task_id, description, subagent_type, tool_use_id}` and `system:task_progress {task_id, description, last_tool_name, usage.total_tokens}` (`system:background_tasks_changed`, `system:thinking_tokens`, `system:hook_started/progress/response` also appear). The reducer folds `task_*` into `chat-store.liveTasks` (a `Record<task_id, LiveTask>`), updated on started/progress and **cleared on `result`** (tasks are per-turn); `SubagentPanel` shows a live "Running" section above the grouped subagent output. The task events carry the predicates to build a fuller `/workflows`-style phase/agent/token view later.
- **Write the first user message immediately after spawn.** Empirically the CLI only emits its `system/init` event once a prompt is waiting on stdin — gating on init first deadlocks. The process stays alive across turns: one conversation = one process + one `session_id`, and later turns are written via a separate `chat:send` IPC to the live process (multi-turn keeps context). `Stop` kills it and emits `stopped` (the `{"type":"interrupt"}` control message is not reliable); after a stop the same `sessionId` can respawn a fresh process via `chat:send`.
- **Slash commands come from the CLI, not the app.** The `system/init` message carries `slash_commands` (array of bare names, incl. namespaced skills like `design-taste-frontend`); `chat-host.ts` re-emits it as `{type:'slash-commands',commands}` so the renderer can show a `/` picker. `ChatPanel.tsx` handles `/help` `/theme` `/new` locally and forwards every other `/cmd` to the CLI as the prompt. Note `/clear` forwards and runs, but does not actually reset conversation context in stream-json mode (verified).
- **FCC proxy wiring.** The FCC env goes on the subprocess `env` (spread over `process.env`): `ANTHROPIC_BASE_URL=FCC_BASE_URL` (`http://127.0.0.1:8082`), `ANTHROPIC_AUTH_TOKEN=freecc`, `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`, and `CLAUDE_CODE_AUTO_COMPACT_WINDOW=<autoCompactWindow * 1000>` where `autoCompactWindow` (thousands of tokens) is user-configurable in chat settings and lives in `src/main/chat/config.ts`. FCC is a request-transforming gateway, not a dumb relay. The gateway also serves `GET /v1/models` — the chat model picker fetches it (`src/main/chat/models.ts`, IPC `chat:models`) and the renderer filters to claude-related entries.
- **The `canUseTool` permission bridge never fires through the FCC proxy.** The chat uses `--permission-mode acceptEdits` — agent edits are auto-accepted and surfaced via the diff view, not gated per-tool. Local hooks (PreToolUse/PostToolUse/SessionStart) do run in the subprocess; interactive per-tool approval is not reachable.
- **Subprocess hardening (verified empirically).** The CLI spawn uses `windowsHide: true` (a packaged GUI would otherwise flash a console window per turn); `stop()` tree-kills on Windows via `taskkill /pid <pid> /T /F` (plain `kill()` leaks grandchildren — Bash-tool / MCP-server node children); a bounded stderr tail is folded into error messages; stdin writes to a dead child are guarded and EPIPE swallowed (an unhandled stream `error` would crash main); and `sawResult` is cleared **per turn** in `send()` so a mid-turn CLI death always emits an error — without that, the renderer's `running` flag wedges forever.
- **`resolveCliBinary()` works in the packaged build** via `app.getAppPath()` + `process.resourcesPath/app.asar.unpacked`, and `package.json` `build.asarUnpack` ships `claude.exe` out of the asar (an executable inside `app.asar` can't be spawned).
- **CLI stream-json message shapes** equal the SDK's: no top-level `tool_use` type — tool calls are content blocks inside `assistant` messages, results are `tool_result` blocks inside `user` messages. The renderer reducer (`src/renderer/src/chat/chat-reducer.ts`) dispatches on `message.type` (`assistant` | `user` | `result` | `system`); `system/init` and `system/hook_*` events are ignored by the reducer. `chat-host.ts` forwards raw events and also emits a `session-id` event from `result.session_id`.
- **Chat settings modal** opens from the gear as the first flex child of `.chat-input` (ChatPanel). `ChatSettingsModal.tsx` has four tabs: Settings (model picker / max-turns / auto-compact / plan toggle + `sessionUsage` cumulative tokens), History, MCP, Config. The model picker shows curated latest Claude models (friendly labels from `claudeLabel()`, `CURATED_CLAUDE_MODELS` in settings-store) plus a live "Available on gateway" group auto-detected from `/v1/models` — all four curated ids were verified to route through the gateway. History/MCP/Config lists load via IPC into **local component state** — never a zustand selector that returns a fresh array (a `.filter()` in a selector caused "Maximum update depth exceeded" / white screen once).
- **Chat history persistence** lives in main (`src/main/chat/history.ts`), JSON files at `app.getPath('userData')/sessions/<rendererSessionId>.json`. The transcript is accumulated in `chat-host.ts`'s single `emit()` funnel — every chat event (synthetic `user-message` + raw CLI `assistant`/`result`/`session-id`) is recorded; `result` flushes to disk, `start()` flushes superseded sessions **before** clearing them, `stop()`/`stopAll()` flush. History files survive renderer reloads/restarts. Record ids (renderer sessionIds, `s-<ts>-<rand>`) pass a `/^[A-Za-z0-9._-]+$/` path guard in `read`/`remove`.
- **Resume (`--resume`) is now used** by the History tab: `openHistory()` restores the saved transcript into chat-store, sets `pendingResume` to the saved CLI `session_id`, and the next `send()` spawns via `chatStart(..., { resume })` (the saved folder wins over the currently-open one). Reliability through the FCC proxy is unverified — if resume fails, the restored transcript still displays and the CLI error surfaces in chat.
- **MCP servers are managed via `.mcp.json`** in the open project folder (`src/main/mcp-service.ts` over the sandboxed file-service; IPC `mcp:get`/`mcp:set`). The claude CLI discovers MCP from its cwd (the open folder) at spawn, so edits apply to the next conversation. With no folder open, `getMcpConfig()` returns empty and `setMcpConfig()` throws "No folder open".
- **Program settings and chat settings are separate modals.** The titlebar gear opens "Program settings" (editor font size, auto-save); the chat gear opens "Chat settings" (model/max-turns/plan toggle + history + MCP). `MODEL_SUGGESTIONS` lives in `settings-store.ts`. Auto-save is a debounced (800ms) save on editor change, and is **skipped for `agentModified` files** — auto-saving would clobber a Claude edit on disk and corrupt accept/revert.
- **Command palette (Ctrl+Shift+P)** is a top-centered overlay (`CommandPalette.tsx`) listing app commands plus the chat slash commands. Slash commands are NOT sent directly: the palette dispatches `fcc:chat-input` with the completed `"/cmd "`, and ChatPanel fills its input so `submit()` keeps the local-vs-forward logic and the `!root`/`running` guards. "Program Settings"/"Chat Settings" open via `fcc:open-settings` / `fcc:open-chat-settings` CustomEvents (Titlebar/ChatPanel listen).
- **Titlebar menu bar** — `MenuBar.tsx` renders File/Edit/View/Chat/Terminal/Help dropdowns (`-webkit-app-region: no-drag`) reusing the same stores/events as the palette + activity bar. Where the target is another component it dispatches a CustomEvent: `fcc:open-palette` (App), `fcc:open-shortcuts` (Titlebar → same popover as `?`), `fcc:term-new` / `fcc:term-clear` / `fcc:term-run` (TerminalPane). The dropdown is `position: fixed` at z-1001 over a `.ctx-backdrop` (z-1000), both inside the titlebar's stacking context, and closes on outside click or Escape.
- **Find in files (Ctrl+Shift+F)** runs in main (`file-service.searchContent` — same walk as `searchFiles`, plus a 1 MB file cap, NUL-byte binary skip, and a 1000-hit cap), returns `SearchHit{path,relative,line,text}` over `fs:search-content`. The sidebar has a `sidebarView: 'explorer' | 'search'` (layout-store, ActivityBar buttons). Clicking a hit dispatches `fcc:reveal {path,line}`; Editor applies it in `onMount` via `revealLineInCenter` (the Monaco `<Editor>` remounts per file, so a reveal set before mount is read at mount).
- **Per-hunk diff review** — `DiffView` lists each change hunk (from Monaco `getLineChanges()` + `onDidUpdateDiff`) below the diff with a per-hunk Revert. `revertAgentHunk(path, hunk)` (editor-store) undoes one hunk by splicing the base lines over the current disk content (the tab's content can be stale — the store reads the file first); the agent-modified flag clears only when the whole file equals base. Whole-file Accept / Revert all remain.
- **Claude Code config editor** — the chat settings "Config" tab (`ClaudeConfigTab.tsx`) edits `~/.claude/settings.json` (user) and `<root>/.claude/settings.json` (project) via `src/main/claude-settings.ts` + IPC `claude-settings:get/set`. `mergeSettings` preserves fields the UI doesn't render (hooks, statusLine, enabledPlugins) and replaces `env` (an empty object clears it). **Permission rules are byte-exact strings** (e.g. `Bash(npm run *)`, `mcp__server__tool`) — never re-format them. The user's env often lives in the `claudeCode.environmentVariables` array (VS Code spelling), distinct from the CLI's `env` object the editor writes — leave the array alone. Never write `~/.claude.json` (CLI-managed runtime state).
- **Multi-terminal tabs** — the backend (`terminal-service.ts`) already held a `Map<id, pty>`, so tabs are renderer-only in `Terminal.tsx`: each tab is an always-mounted `TerminalTab` xterm (`.term-body.tab-inactive` hides it; sessions survive switches), the "+" adds, ✕ never closes the last. `preload.onTermData` returns an unsubscribe (`ipcRenderer.removeListener`) — it MUST be called on unmount or listeners accumulate on the shared `term:output` channel. The header is `flex-wrap: wrap` with `.term-tabs` at `min-width: 88px` — in a narrow right-docked column the actions would otherwise crush the tabs out of view.
- **Flexible panel layout** — the `.app` grid is `rows: 34px 1fr auto auto; cols: auto auto auto 1fr` (titlebar / activity-bar + sidebar + center / terminal / statusbar). `layout-store` (persist `fcc-layout`) drives it: `terminalPosition: 'bottom'|'right'`, `chatPosition: 'right'|'center'`, `*Visible`, widths/heights. Activity-bar icons **toggle** their panel (`toggleChat`/`toggleTerminal`, with the active highlight showing what's open); each panel can also close via a header ✕ (chat/terminal headers), and the keyboard toggles (Ctrl+` / Ctrl+Shift+`) behave the same. The terminal fully hides when closed (`.terminal-pane.hidden`, `display:none`) — the pane stays mounted so pty sessions survive hide/show. `DragHandle` has an `invert` prop: right/bottom-docked panels flip the drag delta (dragging toward the window center grows the panel); the left sidebar is **not** inverted. The right side is a `.right-col` flex column (chat on top, optionally the right-docked terminal below). When `chatPosition === 'center'` the chat overlays the editor as `position: absolute; inset: 0` (`.center` is `position: relative`) — the editor stays mounted underneath so Monaco buffers survive; `Editor.openFile` slides the chat back to the side when a file is opened. Switching dock positions remounts the pane, restarting terminal sessions (accepted tradeoff).
- **Custom subagents editor** — the chat-settings **Agents** tab lists/edit/creates `.claude/agents/*.md` (`src/main/claude-agents.ts` mirrors mcp-service; IPC `agents:list/read/save/delete`, renderer `AgentsTab`). It edits the raw frontmatter+body MD (the native Claude Code format); saving locks the frontmatter `name:` to the filename. Creating an agent while no folder is open is rejected, and file-service `assertInside` keeps writes in the root. `listAgents` returns `[]` when `.claude/agents` is absent.
- **Status bar is live + settings show a context-usage bar.** `chat-store.liveStatus` (from `system/status`) drives the status bar's mode · model · effort. `SettingsTab` renders a last-turn token mix via `UsageBar` (cache-write / cache-read / fresh-input / output) — the reducer's `lastUsage` now carries `cacheRead`/`cacheWrite` in addition to `input` (which remains the total input incl. cache) and `output`.
- **Workspace restore** — the open folder is persisted by `explorer-store` (persist `fcc-explorer`, `root` only) and open tabs by `editor-store` (persist `fcc-tabs`, tab paths + `activePath` only — never file content). Restore is centralized in an `App.tsx` mount effect, **in this order**: `window.fcc.openFolderAt(root)` (IPC `fs:open-root` → `file-service.openRootAt`, validates the dir exists then `setRoot`) → `fsList(root)` → re-open each saved tab (re-reads content from disk). The order is load-bearing: `assertInside` throws "No folder open" until `setRoot` runs, so any file IPC before registration rejects; if the folder is gone, both stores are cleared.
- **Claude logo** — `IconClaude` in `icons.tsx` is the official filled Claude mark (can't use the stroked `Svg` wrapper; it takes `currentColor` and renders orange in the accent-tinted containers). Used in the chat empty state, the agent banner, and the changes strip. The chatbox is compact: the textarea auto-grows 34–96px (JS cap matches the CSS max-height), with 34px send/gear buttons and a slim footer.
- **npm 24 `allowScripts` policy** blocks postinstall scripts for `electron`/`esbuild` by default; they are whitelisted in `package.json`. There is deliberately **no `postinstall` script** — node-pty ships N-API prebuilds, so `electron-builder install-app-deps` (which would trigger a node-gyp rebuild) is skipped.
- **node-pty must be externalized** in `electron.vite.config.ts` (`externalizeDepsPlugin()` on main+preload). Bundling node-pty breaks `conpty.node` loading. The `@anthropic-ai/claude-agent-sdk` package stays as a dependency solely to ship the bundled `claude` binary (platform packages like `claude-agent-sdk-win32-x64`); the app no longer imports the SDK — `chat-host.ts` spawns the binary directly.
- **Sandboxed renderer**: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. All Node capability must go through the preload bridge.
- **Custom titlebar overlay.** The window is frameless (`titleBarStyle: 'hidden'` + `titleBarOverlay` height 34 in `src/main/index.ts`). The HTML `.titlebar` must keep `padding-right: 150px` to reserve the native caption-button overlay. The caption buttons are re-tinted via the `setTitleBarOverlay` IPC, fired from the App.tsx theme effect with hardcoded hex pairs (`#0e1013`/`#a0a8b4` dark, `#faf8f6`/`#6f665d` light) that must stay in sync with the CSS theme variables.
- **Theme switching** is `data-theme` on `<html>` + CSS variables (`--bg-*`, `--text-*`, `--accent`). Dark and light are both defined in `styles.css`; store the `theme` in `layout-store` (zustand-persist, key `fcc-layout`). `Ctrl+K Ctrl+T` toggles it. Never hardcode a theme color in a component — components must use `var(--…)`; SVG presentation attributes (which reject `var()`) are colored via inline `style`.
- **Design tokens + motion conventions** (all in `styles.css`): `--shadow-1/2/3` (floating surfaces — modals/palette/ctx-menu — use `--shadow-3`), `--surface-highlight` (inset 1px lit top edge on panels), `--space-1..5`, `--fs-xs..lg`, and `--transition` (220ms). Interactive state changes should use `--transition`; entrance animations live as keyframes `modal-in`, `backdrop-in`, `fade-up` (modals/backdrops/bars). The 2026 polish pass added these everywhere — keep new elements consistent. Modals close on Escape and focus/restore the trigger via `useModalFocus` (`src/renderer/src/hooks/useModal.ts`, attach the ref + `tabIndex={-1}` to the panel). All animation respects the global `@media (prefers-reduced-motion: reduce)` kill switch.
- **Dirty-tab discard guard.** Closing an unsaved tab only arms it (`closingPath` in `editor-store`); a second ✕ click discards. `closeOthers`/`closeAll` refuse while any tab is dirty. Any other tab interaction cancels the armed state. The UI signals the armed state with a `.tab.closing` red tint + pulsing dot.
- **App icons.** `resources/icon.svg` is the single source; `npm run icons` rasterizes it (in a hidden Electron window) to `build/icon-*.png` + `icon.ico` used by the BrowserWindow and the NSIS installer. The generator window and page background must stay transparent — `capturePage` only keeps the icon's alpha channel that way. The mark color is `#d97a55` so it reads on both light and dark. Icons are read from disk at window creation; changing them needs a dev restart (HMR won't pick them up).

## File-system safety (main process)

`src/main/file-service.ts` guards every path operation:

- `assertInside()` rejects any path escaping the open folder (lexical `isInside` + realpath-based symlink/junction check).
- `deleteEntry` refuses to delete the project root.
- `renameEntry` refuses to overwrite an existing target; `createEntry` uses `{ flag: 'wx' }`.
- Directory listing skips `node_modules`, `.git`, `.next`, `dist`, `out`, `release`.

Terminal and editor UI components are not covered by tests. `tests/` is **git-ignored (dev-only)** — run locally, not shipped or committed.

- `npm run smoke` is the only test that needs a live FCC server; everything else is offline.

## FCC server

- `fcc-manager.ts` polls `GET /health` every 5s and pushes status to the status bar. If offline, "Start" spawns `fcc-server` (override binary via `FCC_SERVER_BIN`, port via `FCC_PORT`, token via `FCC_AUTH_TOKEN`, base URL via `FCC_BASE_URL`).
- **Install detection.** `detectInstall()` resolves `fcc-server` *without executing it* (FCC_SERVER_BIN override → `~/.local/bin` → PATH via `where`/`which`) and probes Python 3.14 + `uv`. The status bar shows "FCC not installed" + a Set up button when missing; `FccSetupModal` shows the platform-correct install command (PowerShell/curl bootstrap — FCC is a Python/uv tool, **not** an npm package) with a copy button, plus a PATH note when the binary is in `~/.local/bin` but off PATH. `startServer()` uses the resolved path and swallows spawn errors so a missing binary can't crash the app.
- **The app owns the server lifecycle.** `autoStartServer()` (called on window creation) spawns `fcc-server` in the background when installed + offline — no need for the FCC tray app. `FccStatus.managed` is true only for a server this app spawned; the status bar shows **Stop server** then, and `fcc:stop` (`stopServer()`) kills it via `taskkill /pid <pid> /T /F` (win32, detached so it survives app quit). `will-quit` stops our own server. A server already running (e.g. started by the tray app) is detected online and left untouched — never killed.
- Chat model and turn limit default from env: `FCC_CHAT_MODEL` (default `claude-haiku-4-5-20251001`), `FCC_CHAT_MAX_TURNS` (default 50). The renderer's settings UI overrides them at runtime: `settings-store` (zustand-persist `fcc-settings`) is the source of truth, pushed to main via the `settings:set` IPC which calls `setChatConfig` (see `src/main/chat/config.ts`); `chat-host.ts` reads `getChatConfig()` at session start. Editor font size also lives in `settings-store`.
